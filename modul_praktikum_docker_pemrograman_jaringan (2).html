Gambaran Umum Praktikum

Pada praktikum ini Anda akan membangun sistem monitoring IoT sederhana menggunakan beberapa container yang saling terhubung.

Arsitektur sistem yang akan dibuat:

  1. Simulator menghasilkan data sensor palsu secara berkala.
  2. Nginx Gateway menerima request dari sisi publik dan meneruskan API ke backend.
  3. Flask Backend menerima data sensor dan menyiapkan endpoint untuk dashboard.
  4. Redis menyimpan riwayat log sensor terbaru.
  5. Dashboard Web mengambil data dari API dan menampilkan pembaruan real-time.

Target akhir praktikum: saat simulator dijalankan, dashboard pada browser harus menampilkan data sensor yang terus berubah setiap beberapa detik.

Tujuan dan Capaian Pembelajaran

Setelah menyelesaikan modul ini, mahasiswa diharapkan memahami konsep containerisasi untuk sistem IoT sederhana.

Kompetensi 1Membuat struktur kerja proyek Docker secara rapi
Kompetensi 2Menyusun layanan backend, database, dashboard, dan gateway
Kompetensi 3Memahami pemisahan jaringan internal dan publik
Kompetensi 4Melakukan verifikasi hasil dengan simulator data real-time

TAHAP 2: Pembuatan File Proyek

Membuat seluruh file inti langsung dari Terminal agar mengurangi risiko salah nama atau ekstensi tersembunyi.

Belum selesai

Pada tahap ini Anda akan membuat semua file yang diperlukan untuk sistem. Jalankan blok berikut satu per satu.

  1. Membuat requirements.txt
    requirements.txt 
    cat << 'EOF' > requirements.txt
flask
redis
EOF
  2. Membuat Dockerfile untuk backend Python
    Dockerfile 
    cat << 'EOF' > Dockerfile
FROM python:3.9-alpine
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]
EOF
  3. Membuat app.py sebagai backend API
    app.py 
    cat << 'EOF' > app.py
import json, time
from flask import Flask, request, jsonify
import redis

app = Flask(__name__)
db = redis.Redis(host='iot_db', port=6379, db=0, decode_responses=True)

@app.route('/api/data', methods=['POST'])
def receive_data():
    try:
        data = request.json
        data['timestamp'] = time.strftime('%Y-%m-%d %H:%M:%S')
        db.lpush('sensor_logs', json.dumps(data))
        db.ltrim('sensor_logs', 0, 9)
        return jsonify({"status": "success", "message": "Data received"}), 201
    except Exception as e:
        return jsonify({"status": "error", "message": str(e)}), 400

@app.route('/api/data', methods=['GET'])
def get_data():
    logs = db.lrange('sensor_logs', 0, -1)
    return jsonify([json.loads(log) for log in logs]), 200

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
EOF
  4. Membuat nginx.conf sebagai gateway / reverse proxy
    nginx.conf 
    cat << 'EOF' > nginx.conf
server {
    listen 80;
    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
    location /api/ {
        proxy_pass http://iot_app:5000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        add_header Access-Control-Allow-Origin *;
    }
}
EOF
  5. Membuat index.html untuk dashboard monitoring
    index.html 
    cat << 'EOF' > index.html
<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="UTF-8">
  <title>IoT Dashboard Monitor</title>
  <style>
    body { font-family: sans-serif; padding: 20px; background: #f4f4f4; }
    .container { background: white; padding: 20px; border-radius: 8px; max-width: 800px; margin: auto; box-shadow: 0 4px 8px rgba(0,0,0,0.1); }
    table { width: 100%; border-collapse: collapse; margin-top: 15px; }
    th, td { padding: 12px; border-bottom: 1px solid #ddd; text-align: left; }
    th { background: #0056b3; color: white; }
    .live { color: red; font-weight: bold; animation: blink 1s infinite; }
    @keyframes blink { 50% { opacity: 0; } }
  </style>
</head>
<body>
  <div class="container">
    <h2><span class="live">●</span> Live Sensor Data</h2>
    <table>
      <thead>
        <tr><th>Waktu</th><th>ID Perangkat</th><th>Suhu (°C)</th><th>Kelembapan (%)</th></tr>
      </thead>
      <tbody id="data-table"></tbody>
    </table>
  </div>
  <script>
    function fetchData() {
      fetch('/api/data')
        .then(res => res.json())
        .then(data => {
          let html = '';
          data.forEach(row => {
            let tempColor = row.temperature > 30 ? 'red' : 'green';
            html += `<tr><td>${row.timestamp}</td><td><b>${row.device_id}</b></td><td style="color:${tempColor}; font-weight:bold;">${row.temperature}</td><td>${row.humidity}</td></tr>`;
          });
          document.getElementById('data-table').innerHTML = html;
        });
    }
    setInterval(fetchData, 2000);
    fetchData();
  </script>
</body>
</html>
EOF
  6. Membuat simulator.py sebagai perangkat IoT virtual
    simulator.py 
    cat << 'EOF' > simulator.py
import time, random, requests

URL = "http://iot_gateway/api/data"
print("Memulai Simulasi IoT... Tekan Ctrl+C untuk berhenti.")

while True:
    payload = {
        "device_id": random.choice(["ESP32_A", "ESP32_B", "Node_Lora_1"]),
        "temperature": round(random.uniform(25.0, 35.0), 2),
        "humidity": round(random.uniform(50.0, 80.0), 2)
    }
    try:
        res = requests.post(URL, json=payload)
        print(f"[{res.status_code}] Terkirim: {payload}")
    except Exception:
        print("Menunggu koneksi Gateway...")
    time.sleep(3)
EOF

Penjelasan fungsi masing-masing file:

  • requirements.txt menyimpan daftar library Python yang dibutuhkan backend.
  • Dockerfile mendefinisikan cara image backend dibangun.
  • app.py menerima data sensor, menyimpannya ke Redis, dan menyajikannya kembali lewat API.
  • nginx.conf memisahkan akses halaman dashboard dan akses API.
  • index.html membuat tampilan dashboard sederhana dengan update otomatis.
  • simulator.py bertugas meniru perangkat IoT sungguhan yang mengirim data secara periodik.

Tips verifikasi: setelah semua file dibuat, jalankan ls untuk memastikan keenam file muncul pada folder proyek.

Cek Isi Folder 
ls -lah
3

TAHAP 3: Build Image dan Pembuatan Network

Mengubah source code menjadi image Docker dan menyiapkan pemisahan jalur komunikasi container.

Belum selesai

Masih dari folder ~/Modul_Docker_IoT, jalankan perintah berikut:

Build Image Backend 
docker build -t my_iot_app:latest .
Membuat Network 
docker network create --internal -d bridge backend_net
docker network create -d bridge public_net

Penjelasan:

  • docker build membuat image bernama my_iot_app:latest dari Dockerfile di folder saat ini.
  • backend_net adalah jaringan internal untuk backend dan database agar tidak terekspos langsung.
  • public_net adalah jaringan yang dipakai gateway untuk menerima akses dari pengguna / browser.
  • Pemisahan jaringan seperti ini membuat arsitektur lebih terstruktur dan lebih aman.

Hasil yang diharapkan:

  • Build selesai tanpa error.
  • Output docker network ls menampilkan backend_net dan public_net.
Verifikasi Image dan Network 
docker images | grep my_iot_app
docker network ls

Masalah umum:

  • docker build gagal karena file requirements.txt atau app.py belum ada.
  • Network sudah pernah dibuat sehingga Docker menampilkan pesan nama network sudah dipakai. Jika itu terjadi, tidak perlu panik — cukup cek dengan docker network ls.
4

TAHAP 4: Menjalankan Container dengan Urutan Benar

Menyalakan semua service sesuai urutan agar gateway dapat menemukan backend dan dashboard berjalan normal.

Belum selesai

Ikuti urutan berikut dengan tepat. Ini adalah bagian penting agar startup sistem tidak bermasalah.

  1. Menyalakan Redis
    Redis 
    docker run -d --name iot_db --net backend_net redis:alpine
  2. Menyalakan backend Python
    Flask Backend 
    docker run -d --name iot_app --net backend_net my_iot_app:latest
  3. Membuat container gateway terlebih dahulu (belum dijalankan)
    Nginx Gateway 
    docker create --name iot_gateway --net public_net -p 8080:80 \
-v $(pwd)/nginx.conf:/etc/nginx/conf.d/default.conf \
-v $(pwd)/index.html:/usr/share/nginx/html/index.html \
nginx:alpine
  4. Menghubungkan gateway ke jaringan backend
    Network Bridge 
    docker network connect backend_net iot_gateway
  5. Menjalankan gateway setelah semua jalur siap
    Start Gateway 
    docker start iot_gateway

Mengapa urutannya penting?

  • Redis harus aktif lebih dulu karena backend memerlukannya untuk menyimpan log.
  • Backend Flask harus aktif sebelum gateway menerima trafik API.
  • Gateway dibuat dengan docker create dulu agar bisa dihubungkan ke dua network sebelum dijalankan.
  • Jika gateway langsung dijalankan terlalu cepat, ada kemungkinan route API belum siap sehingga muncul error pada akses dashboard.

Verifikasi tahap ini:

Cek Container Aktif 
docker ps

Pastikan minimal terlihat container iot_db, iot_app, dan iot_gateway.

Masalah umum:

  • Nama container sudah dipakai. Hapus dulu container lama dengan docker rm -f iot_db iot_app iot_gateway.
  • Port 8080 bentrok dengan aplikasi lain. Ganti mapping port misalnya menjadi -p 8081:80.
  • Nginx gagal start karena file nginx.conf tidak ditemukan atau syntax konfigurasi salah.

TAHAP 5: Simulasi dan Pembuktian Hasil

Menghidupkan dashboard dan simulator untuk membuktikan bahwa seluruh sistem berjalan real-time.

Belum selesai
  1. Buka dashboard di browser

    Akses alamat berikut:

    URL Dashboard 
    http://localhost:8080
  2. Jalankan simulator IoT
    Menjalankan Simulator 
    docker run -it --rm --name iot_simulator --net public_net \
-v $(pwd):/app -w /app python:3.9-alpine \
sh -c "pip install requests && python simulator.py"

Alur data saat simulator berjalan:

  1. Simulator membuat payload sensor acak.
  2. Payload dikirim ke http://iot_gateway/api/data.
  3. Nginx meneruskan request ke backend Flask.
  4. Flask menambahkan timestamp dan menyimpan data ke Redis.
  5. Dashboard memanggil endpoint /api/data setiap 2 detik lalu memperbarui tabel.

Hasil akhir yang harus muncul:

  • Pada terminal simulator, terlihat log seperti [201] Terkirim: {...}.
  • Pada browser, tabel dashboard mulai terisi data sensor terbaru.
  • Baris data akan berubah / bertambah sesuai interval pengiriman simulator.

Untuk menghentikan simulasi: tekan Ctrl + C pada terminal yang menjalankan simulator.

Checklist Verifikasi Akhir

Gunakan daftar ini untuk memastikan sistem benar-benar berhasil dibangun.

  • Folder proyek berisi semua file yang dibutuhkan.
  • Image my_iot_app:latest berhasil dibuat.
  • Network backend_net dan public_net sudah ada.
  • Container iot_db, iot_app, dan iot_gateway dalam status berjalan.
  • Dashboard dapat diakses di browser.
  • Simulator mengirim data dengan status 201.
  • Dashboard menampilkan data sensor secara real-time.
Paket Perintah Verifikasi 
ls -lah
docker images | grep my_iot_app
docker network ls
docker ps
docker logs iot_app --tail 20
docker logs iot_gateway --tail 20

Troubleshooting Cepat

Jika hasil tidak sesuai harapan, gunakan panduan singkat berikut.

Dashboard kosong
Pastikan simulator sedang berjalan, gateway aktif, dan endpoint /api/data bisa diakses melalui browser atau curl.
Container backend mati
Cek log dengan docker logs iot_app. Biasanya karena Redis belum berjalan atau nama host Redis salah.
Nginx error
Pastikan file nginx.conf benar dan mount file menggunakan path yang sesuai dari folder kerja.
Port 8080 tidak bisa dibuka
Kemungkinan port dipakai aplikasi lain. Ubah mapping port saat membuat gateway, misalnya -p 8081:80.
Ingin mengulang dari awal
Hapus container lama lalu ulangi tahap eksekusi. Gunakan perintah cleanup di bagian bawah halaman ini.

Cleanup / Menghapus Resource Setelah Praktikum

Bagian ini opsional, tetapi berguna jika Anda ingin mengulang praktikum dari awal atau membersihkan resource Docker.
